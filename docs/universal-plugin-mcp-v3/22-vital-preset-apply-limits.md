# 22. Vital preset apply: what carries fully, what does not, and the wavetable problem

Дата: 2026-10-17. Автор: сессия P38 (см. журнал `IMPLEMENTATION-STATUS.md` §39).
Все числа — из живых замеров на инстансе Vital VST3i **1.5.5** (трек 15 / индекс 14);
evidence каждого прогона лежит в `%LOCALAPPDATA%\reaper_reapy_mcp\run_artifacts\…__vital-preset-research__*`
(P32: в репозиторий evidence не попадает). Репозиторий хранит инструменты и записи, не их вывод.

Документ отвечает на один вопрос: **если я попросил `plugin_presets(op="apply", preset=…)`, что именно
из этого пресета окажется в плагине — и что будет молча не так.**

---

## 1. Три исхода применения (и как их увидеть в ответе)

Ответ инструмента — schema-2 конверт. Признак «пресет лёг не весь» — `partial: true` плюс блок
`preset_carry {gaps, reasons}` и список `gaps[]`, где каждый не перенесённый кусок назван с причиной.

| исход | что это значит | как видно |
|---|---|---|
| **ложится целиком** | контролы, элементы (`lfos`, `custom_warps`, `random_values`), метки, сэмпл, маршруты, которые билд принимает, и таблица — **только если она не растит слот** | `verdict=ALL_VERIFIED`, `partial` покрыт необязательными gap'ами (см. ниже) |
| **ложится частично** | часть пресета не может быть перенесена этим каналом; остальное применяется и проверяется | `partial: true`, каждый `gaps[].reason` из таблицы §4 |
| **отказывается целиком** | правило зависимостей или ошибка — транзакция откатывается к захваченному состоянию | `ok: false`, `error.code`, `outcome.verdict` из `FAILED_*` |

Даже «частично» — это **проверенный** результат: каждый юнит записи читается назад и сравнивается,
а `outcome.channels` содержит построчную таблицу «записано / прочитано / совпало».

## 2. Таблицы (wavetables): измеренный масштаб проблемы

`.vital`-файл несёт до трёх wavetable-слотов (`settings.wavetables[]`), каждый — группы компонентов
с кадрами (`keyframes[].wave_data`, base64 float32, 2048 сэмплов на кадр). **Много-кадровая таблица**
— это и есть «3D»/спектральная: `Oscillator N Wave Frame` (и маршруты на него) двигает движок по
кадрам.

**Стратифицированная выборка библиотеки** (`probe_p38_wavetable_corpus.py`, run
`20261017T201813Z__vital-preset-research__17008`; 150 файлов, шаг 14 по списку, отсортированному по
размеру — то есть выборка покрывает корпус, а не только крупные файлы):

| измерение | значение |
|---|---|
| файлов в библиотеке | 2226 (2.19 ГБ) |
| в выборке | 150 |
| все слоты = Init-таблица (применяются без потерь по таблицам) | **23 / 150** |
| несут минимум одну **кастомную** таблицу | **127 / 150 (85 %)** |
| кастомных таблиц в выборке | 246 |
| из них одно-кадровых / много-кадровых («3D») | 123 / **123** |
| **проходят guard** | **6** |
| **отклоняются** | **240** (в том числе **все 123 много-кадровых**) |
| payload кастомной таблицы: min / медиана / max | 649 / **87 856** / 1 469 727 Б |
| измеренно-безопасный payload (`VERIFIED_PAYLOAD_BYTES`) | **11 159** Б |

Прошедшие шесть — одно-кадровые таблицы, чей payload **ровно равен** Init-размеру (11 149–11 159 Б):
замена равной длины, а не рост. Правило guard'а простое и относительное (`wavetables.py`,
`check_writable`): не расти ни в кадрах, ни в total samples, ни в content-bytes, ни в payload; при
неизвестном текущем слоте — не превышать измеренно-безопасный размер.

**Почему это защита, а не лень.** В P30 измерено: растущий payload **не долетает** (плагин оставляет
прежнюю сериализацию), а одна попытка с несовпадающим `version` **уронила `reaper.exe`**. Поэтому
apply «чужого» пресета с крупной таблицей честно отказывается её нести.

**Что слышит пользователь.** Пресет, который опирается на свою таблицу, звучит как таблица, **уже
лежащая в слоте** (у свежего инстанса — Init, то есть простая пила), а в ответе инструмента стоит
`partial: true` и gap `wavetable_growth_refused`. Ровно этот случай — `House Bass` (SNFK): в файле
1 кастомная 8-кадровая таблица, она отклонена; применены 44 контрола, метки и сэмпл.

**Второй, более коварный случай.** `LD - Future Saw` (Florixel) **вообще не несёт кастомных таблиц**
— все три слота Init, а файл меняет **30 контролов** (компрессор, EQ, `filter_fx`, реверб, volume,
polyphony, portamento) и оставляет все `osc_*` на Init. Он применяется **полностью и верно**, но
звучит как инитовский пилообразный тон — потому что он таким и является. Отличить его от «сломанного
apply» можно только сравнением с Init-состоянием: см. §3.

## 3. Как заранее понять, приедет ли пресет целиком

Практическая последовательность (все — существующие инструменты, ничего дописывать не нужно):

1. `plugin_presets(op="search", query=…, style=…)` — найти кандидата;
2. `plugin_presets(op="apply", dry_run=true, preset=…)` — посмотреть `counts` и `gaps`:
   * `counts.wavetables_requested` / `wavetables_declined` — сколько слотов пресет несёт и сколько
     из них отказано (в примерах выше: 3 запрошено / 2 и 1 отказаны);
   * `counts.routes_skipped_known_drop`, `gaps[].reason` — что ещё не поедет (§4);
3. если таблица критична — сверить её размер с Init: payload ≤ 11 159 Б и один кадр = шанс, что
   приедет; много-кадровая = не приедет;
4. после реального применения — сверить документ с файлом (это делает приёмочная проба
   `probe_p38_apply_timed.py`: `comparison.controls_equal` / `mismatch`, `labels_ok`).

Полезно знать: «тонкость» пресета (сколько контролов он реально меняет относительно Init) — не
дефект применения. `LD - Future Saw` меняет 30 контролов, `BASS Bizzare Future` — 140; оба корректны в
своих пределах.

## 4. Полный список того, что apply не несёт (и почему)

| `gaps[].reason` | что не переносится | измеренная причина |
|---|---|---|
| `wavetable_growth_refused` | таблица, растущая слот | рост не долетает; один случай уронил `reaper.exe` (P30) |
| `destination_dropped_by_plugin` / `route_dropped_by_plugin` | маршрут, чей destination билд не знает | плагин принимает запись и выбрасывает пару при пере-сериализации (18 из 42 маршрутов в приёмочном пресете) |
| `growth_over_budget` | значение, чей СОбственный рост выше полосы (длинные `comments`, массивы точек LFO) | запись выше полосы игнорируется молча; элемент едет целиком или не едет вовсе |
| `slot_text_dropped_with_pair` | поля `modulation_N_*` слота, чей маршрут не поехал | плагин **выбрасывает текст неактивного слота** (активность ключуется по destination) — запись такого поля принимается и стирается при пере-сериализации, унося с собой весь батч (измерено 2026-10-17) |
| `host_owned_parameter` | `beats_per_minute` | темп ведёт хост (REAPER), плагин следует за проектом |
| `guarded_rule_subject` | значения под правилом, которое объявлено, но не вычислимо (`fm_needs_modulator`) | слой отказывает, а не делает вид, что правило выполнено |
| `sample_growth_over_budget` | payload сэмпла, растущий документ сверх бюджета | тот же закон роста; плюс у сэмпла своя измеренная задержка 4 сэмпла |
| `modulation_curve_not_carried` | нелинейная кривая маршрута (`line_mapping`) | провайдер не объявляет запись `line_mapping`; маршрут едет с линейной формой |
| `inactive_slot_text_skipped` | текст пустого слота модуляции | плагин ключует активность по destination; текст не влияет на звук |
| `derived_leaf_not_restored` | (только в откате) лист, который плагин выводит сам | писать его нельзя и проверить нечего |

## 5. Что в этой области **не** проверено (и не должно читаться как «работает»)

1. **Форма границы записи — частично объяснена, частично нет.** Изначально казалось, что правило —
   про **дельту текста блока** (`+44` долетает, `+48` нет). Живая лестница (2026-10-17, пробы
   `probe_p38_framing_live.py` / `probe_p38_growth_limit.py` / `probe_p38_total_cap.py`) показала, что
   это **не** так: при **одной и той же** дельте блока `+44` рост значения на **32** символа долетает,
   а на **33** — нет; а пары «20+13» (суммарно 33, дельта блока 36) долетают, «20+20» (сумма 40,
   дельта 44) — уже нет. Что измерено точно:

   | случай | рост JSON | рост значения | дельта блока | результат |
   |---|---|---|---|---|
   | один путь | +32 | 32 | +44 | **долетел** |
   | один путь | +33 | 33 | +44 | **не долетел** |
   | два пути | +33 (20+13) | ≤20 | +36 | **долетел** |
   | два пути | +40 (20+20) | 20 | +44 | **не долетел** |
   | два пути | +48 (20+28) | 28 | +56 | **не долетел** |
   | три пути | +56 (20+32+4) | ≤32 | +56 | **не долетел** |
   | сжатие (pad) 8…64 | ≤ 0 | — | 0 | **все долетели** |

   То есть лимит лежит **по JSON-тексту** (а не по base64/блоку), причём зависит и от одного
   значения (≤ 32), и от суммы; где именно верхняя граница суммы (между 33 и 40) — **не измерено**.
   Практический вывод уже зашит: упаковщик держит оценку батча ≤ 24, а один путь — ≤ 24, и все
   измеренные случаи внутри этого лежат.
   **Не проверено до конца:** почему при 33 на одном пути запись игнорируется, а при 33 на двух —
   проходит (гипотеза «буфер на значение + буфер на документ» не проверялась). Наблюдаемая разница
   «долетел / проигнорирован» однозначна и полезна: у долетевшей записи read-back — это
   **пере-сериализация плагина** (первые расхождения внутри base64), у проигнорированной блок
   **побайтово прежний**.
2. **Юнит 34/38 тяжёлой цепочки — объяснён и исправлен.** Он падал на `modulation_35_amount`,
   `modulation_38_bipolar`, `modulation_41_amount` — то есть на полях **неактивных** слотов, чью пару
   плагин выбросил (§4). Теперь поля слота, чей маршрут не поехал, пропускаются вместе с ним
   (`slot_text_dropped_with_pair`). Повторный прогон той цепочки — следующий замер.
3. **Точная граница по типам записей.** Лестницы гонялись на строках (метки, `comments`); числовые
   значения не проверялись (их вклад — длина repr).
4. **Которые именно destination'ы билд принимает.** Профиль перечисляет 316 имён; часть из них этот
   билд выбрасывает. read-only канала для этого не найдено — узнаётся записью (мемо
   `vital_destination_drops.json` копит факты по билду). Первое применение всегда платит за
   неизвестность.
5. **Сэмпл: точная величина рекванта.** Три записи ложились с остатком 0, четвёртая дала 1060/44096
   сэмплов на ±1 LSB (2.4 %). Вердикт теперь принимает один шаг в пределах измеренной полосы, но
   почему реквант включается не всегда — не объяснено.
6. **`op="init"`** — типизированный отказ (`init_artifact_not_recorded`): Init этот билд строит в
   коде, измеренного артефакта нет.

## 6. Чем это измерено (воспроизведение)

```powershell
$N = "$env:LOCALAPPDATA\reaper_reapy_mcp\run_artifacts\20261016T162339Z__vital-preset-research__notes"

# состав и стоимость: где уходит время на один state-юнит
py -3.11 "$N\probe_p38_unit_cost.py"

# таблицы по корпусу: сколько пресетов несут кастомную таблицу и сколько проходит guard
$env:P38_SAMPLE_LIMIT="150"; py -3.11 "$N\probe_p38_wavetable_corpus.py"

# граница роста и поведение «чужого» destination
py -3.11 "$N\probe_growth_boundary.py"
py -3.11 "$N\probe_route_name_vs_growth.py"

# калибровка упаковки батчей: оценка против реальной дельты блока
py -3.11 "$N\probe_p38_batch_calibration.py"

# три представления одного инстанса: документ / параметры (DSP) / файл пресета
py -3.11 "$N\probe_p38_three_views.py"

# приёмка и замер применения через shipping-путь (снимает точку отката сама)
$env:P38_PRESET="User/Presets/…/LD - Future Saw.vital"
py -3.11 "$N\probe_p38_apply_timed.py"
```

Пробы пишут evidence и `report.md` **вне репозитория**; инстанс восстанавливается встроенным
restore (приёмочная проба) либо точкой отката в `run_artifacts\p38-undo\`.

## 7. Что делать дальше (предложение, не решение)

1. **Разобрать фрейминг** (§5.1): проба, которая растёт ровно одним полем item-B за раз (поле длины,
   число строк, артефакт) и каждый раз читает back. Если причина во фрейминге — таблицы становятся
   загружаемыми, и §2 превращается из «предела» в «дефект, который починили».
2. **Разделить §5.2** (юнит 34): прогон с захватом блока до и после того юнита, при отсутствии
   второго писателя. Если виноваты пустые слоты модуляции — это одна правка пресет-слоя
   (не писать `modulation_N_*` для слотов, которые остаются пустыми).
3. **Сделать `partial` заметным**: сейчас «пресет приехал не весь» — это `partial: true` и строчка в
   `gaps[]`. Для пользователя это шум; стоит поднимать в ответе сводку «что не поехало» рядом с
   `counts` (и, возможно, отдельным `warnings[]` в конверте).
4. **Подсказать выбор пресета**: фильтр в `search`/`info` — «приедет целиком / с потерей таблицы»,
   вычисляемый из уже читаемых метаданных (размер и кадры таблицы против Init). Это дешёвая правка
   поверх уже готового каталога.
