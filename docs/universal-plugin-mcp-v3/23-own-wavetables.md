# 23. Свои вейвтейблы и звуковой дизайн через MCP (`plugin_wavetable`)

Этот документ — **протокол**: как агенту (или человеку через MCP) описать собственную волновую
таблицу и положить её в осциллятор Vital, ничего не зная о внутреннем устройстве плагина. Он
намеренно короткий: весь язык описания — **один объект**, а всё остальное (сборка таблицы, проверка,
доставка, откат) уже есть в канале состояния и описано в
[`22-vital-preset-apply-limits.md`](22-vital-preset-apply-limits.md).

## 1. Инструмент

`plugin_wavetable` — три операции:

| op | что делает | нужен хост? |
|---|---|---|
| `write` | собирает таблицу из специи и пишет её в слот осциллятора (по умолчанию `dry_run: true` — план без записи) | да |
| `preview` | рендерит специю **без хоста**: сколько кадров, сколько это стоит в состоянии, спектры концов морфа | **нет** |
| `read` | что лежит в слоте **сейчас**: тип источника, число кадров, `table_id`, спектры кадров | да |

```
plugin_wavetable(instance={...}, op="write", oscillator=1, table={...}, dry_run=False)
plugin_wavetable(op="preview", table={...})          # без instance, если провайдер один
plugin_wavetable(instance={...}, op="read", oscillator=1, frames=16)
```

## 2. Специя (весь язык)

Ровно **один** источник — `shape`, `harmonics` или `samples` — и несколько необязательных полей.

| поле | смысл |
|---|---|
| `shape` | имя формы: `sine`, `triangle`, `saw`, `square`, `pulse`; **список имён** = морф (по кадру на имя) |
| `harmonics` | аддитивный спектр: `[[номер, амплитуда], ...]` (можно третий элемент — фаза в градусах); список таких спектров = морф по кадрам |
| `samples` | сырые отсчёты: список чисел (один кадр) или список списков (кадр на список) |
| `frames` | сколько кадров в таблице (1…256). По умолчанию — сколько элементов перечислено. Больше элементов → промежуточные кадры **интерполируются** |
| `duty` | скважность для `pulse` — **доля цикла** (0…1): 25 % это `0.25`, а не `25` (проценты не принимаются; отказ говорит это прямо) |
| `phase` | фаза для `shape`, в градусах |
| `name`, `author` | метка таблицы (плагин показывает её в браузере); **не** идентичность |
| `full_normalize`, `remove_all_dc` | собственные опции плагина для таблицы |

Кадр — это **ровно 2048 сэмплов** (`kWaveformSize`). Короткий `samples` **ресемплируется**, а не
дополняется нулями: плагин копирует кадр целиком из буфера своего размера, поэтому короткий payload
превратился бы в другую волну, чем та, что описана. Спектр нормализуется по пику (1.0), потому что
тембр — это отношения партиалов, а кадр за пределами ±1 был бы обрезанным.

### Примеры

```jsonc
{"shape": "saw"}                                       // одна пила (как у Init-таблицы плагина)
{"shape": ["sine", "square"], "frames": 16}            // 16-кадровый морф синус -> меандр
{"shape": "pulse", "duty": 0.25}                       // импульс со скважностью 25 %
{"harmonics": [[1, 1.0], [3, 0.4], [5, 0.2]]}          // аддитивная волна
{"harmonics": [[[1,1.0]], [[1,1.0],[2,0.5]]], "frames": 8}   // спектр -> спектр, 8 кадров
{"samples": [[0.0, 0.5, 0.5, -0.5, -0.5, 0.0]]}        // 6 точек, ресемплируются в 2048
```

## 3. Что приходит в ответе

* `preview` — `described` (число кадров, позиции на оси 0…256, размер payload в символах и байтах,
  имя), `frames[]` (для каждого описанного кадра: `peak`, `rms`, `dc`, первые сэмплы и **спектр** —
  амплитуды первых партиалов), `shapes` — словарь имён (чтобы не угадывать);
* `write` — `described`, `delivered` (дошла ли таблица), `gaps[]` с причинами, `outcome` обычного
  канала состояния (сколько единиц, что проверено, что откатывалось);
* `read` — `source_types` (например `Wave Source` или `Audio File Source`), `n_frames`,
  `payload_bytes`, `table_id` и `frame_summaries[]` с теми же числами.

Спектр в ответе делает проверку **сравнением, а не мнением**: «я просил пилу — пришла ли пила»
видно по партиалам (у пилы 1/n: 0.637, 0.318, 0.212…).

## 4. Что происходит под капотом (и почему это безопасно)

Собранная таблица пишется **тем же каналом**, что и любое другое изменение состояния:

1. страж таблицы (это объект таблицы? есть ли в нём волновые данные? есть ли живая версия плагина?);
2. **граница роста**: запись ложится, только если документ вырос не больше чем на ~32 символа —
   иначе плагин её молча игнорирует;
3. **баллон**: если таблица растёт, сначала делается запись, которая делает состояние *больше* таблицы
   (плагин пересоряет по одному полному кадру на ключевой кадр), и таблица приезжает как сжатие;
4. **порядок**: сначала записи, которые документ **сжимают**, потом баллоны — по убыванию комнаты
   (самой большой комнате нужен самый пустой документ);
5. **проверка чтением** каждого юнита и **откат**, если что-то не сошлось;
6. **потолок состояния**: план не идёт туда, где чанк дорожки перевалит за измеренный предел
   читаемости (см. док. 22 §2.3) — отказ приходит **по имени** (`state_ceiling_reached`), а не
   молчанием и не сломанным инстансом.

## 5. Что измерено (2026-10-18, живьём на 1.5.5)

| замер | результат |
|---|---|
| аддитивный спектр (гроул) морфом на 16 кадров в осциллятор 1 | **доставлено**: 16/16 кадров, 9.6 с, никаких gap; `preview` и read-back совпали **точно** (партиалы кадра 0: 0.5473 / 0.3284 / 0.2189 / 0.1642), потому что кадры `Wave Source` — float32 и рекванта нет |
| состояние после записи | 1,170,208 символов при потолке 3,056,250 |
| самый большой пресет семейства (2.9 МБ таблиц) на **свежем** инстансе | 3/3 слота, состояние 3,048,249 (чанк 4,083,632 — ровно у измеренного максимума читаемости) |
| два пресета, чьи таблицы **сами** больше потолка (4.12 МБ) | отказ **по имени** (`state_ceiling_reached`), инстанс остался читаемым |

Вторая серия (`_p40h_own_table_variants.py`) прошла по **всем видам входа** языкa, каждый — записью и
чтением обратно: форма (1 кадр), морф двух ФОРМ (16 кадров), аддитивный спектр (1 кадр), спектр на
кадр (8 кадров), сырые сэмплы короче кадра (ресемплинг), импульс с `duty`/`phase`. Результат: **6/6
доставлено**, у каждого случая прочитанное число кадров совпало с `preview`, а описанные кадры — по
`peak` и партиалам; состояние осталось в диапазоне 0.25–1.25 МБ при потолке 3.06 МБ. Разные входы
проверялись на разных осцилляторах (1, 2 и 3) — то есть путь слота общий и работает для всех трёх.

**Мелочь, которую нашла эта серия:** `duty` в первом заходе был передан как `25` (проценты) —
отказ пришёл типизированный и по имени (`0 < duty < 1`), но **сам ответ не называл единицу**. Теперь
называет и описание инструмента, и `detail` отказа («25 процентов — это 0.25»), потому что
исправление вслепую — это второй тот же прогон. Пином в `test_p40_wavetables.py` закреплено, что
проценты не принимаются молча.

## 6. Границы (честно)

* Таблица пишется целиком: **частичной** записи нет (плагин заменяет таблицу, а не сливает её).
* Точка входа — слот осциллятора (1…3). У сэмплера своего вейвтейбла нет.
* Свой сэмпл (`settings.sample`) этим инструментом не пишется: это другой канал (см. док. 22 §2.4).
* Потолок состояния — это **цена читаемости**: пресет, чьи таблицы в сумме подходят к потолку, может
  не приехать целиком поверх инстанса, который уже держит большую таблицу. Отказ называет и
  спроектированный размер, и потолок, и что делать (загрузить меньшую таблицу или применять на
  свежем инстансе).
* Морф интерполируется линейно между перечисленными элементами; кривые морфа плагина
  (`interpolation_style`) в специи не выражаются — кадры записываются с линейной интерполяцией.
* Звучание не измерялось: измерено то, что плагин **хранит** (по его же read-back).
